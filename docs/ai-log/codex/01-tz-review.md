**2. Рекомендуемый стек и хостинг**

| Слой | Выбор | Обоснование |
|---|---|---|
| Приложение | Next.js + TypeScript | Интерфейс и сервер в одном проекте, меньше стыков за короткий срок |
| Интерфейс | Tailwind CSS + shadcn/ui | Быстрая сборка цельного адаптивного интерфейса |
| Данные | PostgreSQL + Prisma | Связи между студентом, оценками и заявками, миграции, путь к росту нагрузки |
| Авторизация | Better Auth, вход по паролю | Готовый механизм; библиотека по умолчанию хеширует пароли через scrypt |
| Развёртывание | Docker Compose + Nginx + HTTPS | Воспроизводимое размещение и перенос между провайдерами |

Парольная авторизация подтверждена [документацией Better Auth](https://better-auth.com/docs/authentication/email-password); Next.js поддерживает самостоятельный хостинг, перед приложением рекомендует reverse proxy — [документация](https://nextjs.org/docs/app/guides/self-hosting).

**Хостинг: Timeweb Cloud, виртуальный сервер в Москве или Санкт-Петербурге.** У провайдера есть российские площадки, изменение ресурсов сервера и резервные копии. Это подходящий исходный вариант для доступа из РФ, но конкретный сайт обязательно проверить через домашний и мобильный интернет без VPN. [Площадки](https://timeweb.cloud/docs/nashi-data-centry), [возможности серверов](https://timeweb.cloud/services/cloud-servers).

На конкурс достаточно приложения и PostgreSQL на одной ВМ с постоянным хранилищем, ежедневным дампом БД и копией вне этой ВМ. При росте — вынести БД, затем масштабировать приложение. Одна ВМ остаётся единой точкой отказа.

Шрифты, иконки и основные ресурсы хранить вместе с приложением. Для входа жюри использовать заранее созданные аккаунты без обязательных писем, SMS и внешнего OAuth.

**3. Четыре сильные идеи**

Это продуктовые гипотезы под контекст МГИМО; конкретные университетские процедуры нужно подтвердить у студентов.

1. **Деканат по жизненным ситуациям.** Студент выбирает «Еду на обмен» или «Начинаю стажировку» и получает единый маршрут: документы, сроки, заявления и связанные учебные задачи. Один запрос превращается в понятный процесс с общим прогрессом.

2. **Личный языковой маршрут.** Расписание учитывает языковые подгруппы и индивидуальные занятия. Перенос показывает последствия: пересечение с другой парой, изменение окна, необходимость обратиться за согласованием.

3. **Объяснимый учебный радар.** Вместо одного среднего балла — конкретные действия: «Не закрыт зачёт по языку → срок → что сделать → подать обращение». Каждое предупреждение раскрывает исходные данные и правило расчёта; демонстрационные правила явно обозначены.

4. **Проактивный деканат.** Изменение расписания или новый дедлайн сразу предлагает следующий шаг: обновить план, открыть нужный документ, подготовить черновик заявки. Отправку всегда подтверждает студент.

**За 12 дней выбрал бы № 1 как главную особенность и небольшой фрагмент № 3.** Они дают связный демонстрационный сценарий и используют обязательное ядро.

**4. Главные риски**

- **Разрастание объёма.** Пять основных разделов уже требуют полноценной реализации. Кабинет сотрудника, чат, интеграции и несколько ИИ-функций могут съесть срок. Цель — готовая версия 20–21 ноября с резервом на исправления.
- **Утечка между аккаунтами.** Нужны проверки прямых запросов от второго студента, чтения и изменения чужой заявки, выхода и смены аккаунта. Особое внимание — кешированию персональных страниц.
- **Недоступность демонстрации.** Оплата, DNS, сертификат, перезапуск сервера и восстановление БД должны быть проверены заранее. Два аккаунта нужно повторно проверить перед сдачей.
- **Потеря доказательств работы с ИИ.** Этот критерий имеет тот же максимум — 10 баллов — что и каждый из остальных. С начала разработки сохранять постановки задач, документы для агентов, значимые промпты, ошибки ИИ, исправления и результаты проверок. **Встроенный в продукт чат-бот не обязателен по ТЗ.**
- **Ошибочные ответы ИИ.** Если добавлять помощника, ответы должны опираться на подготовленные материалы с указанием источника; учебные статусы и сроки рассчитываются проверяемыми правилами.
- **Условия передачи прав.** Пункты 6.2–6.3 предусматривают безвозмездное отчуждение исключительных прав на отправленные материалы, включая код и промпты. Это существенно для дальнейшего использования проекта командой. [Регламент](https://challenge.mgimo.ai/rules).
