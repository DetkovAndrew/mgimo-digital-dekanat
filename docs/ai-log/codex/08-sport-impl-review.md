## Ответ Codex

После обновления показывается следующая открытая неделя, но `chosen` сохраняет старые ID. На строке 69 получается `undefined.title`. Воспроизвёл в памяти. Добавить редактору `key={weekStart}` и обработку отсутствующего слота.

2. **P1 — студент может закрыть запись всем на оставшийся семестр.** [sport.ts:334](/mnt/c/MGIMO/src/server/dal/sport.ts:334). Каждый последовательный вызов `runDemoDraw` берёт новую открытую неделю. Флаг окружения разрешает любому студенту исчерпать все недели до подачи чужих приоритетов. Ограничить демо фиксированной неделей и разрешёнными аккаунтами; предпочтительно запускать сотрудником.

3. **P1 — защита тестовой БД допускает стирание основной.** [global-setup.ts:9](/mnt/c/MGIMO/tests/integration/global-setup.ts:9). Сравниваются строки URL. Добавление `?application_name=integration` обходит проверку, хотя БД остаётся той же; затем запускается уничтожающий данные seed. Проверять нормализованный адрес БД и разрешённое имя тестовой базы.

4. **P2 — после настоящего дедлайна распределение не происходит.** [sport.ts:139](/mnt/c/MGIMO/src/server/dal/sport.ts:139), [sport.ts:338](/mnt/c/MGIMO/src/server/dal/sport.ts:338). Единственный вызывающий жеребьёвку путь — демо-кнопка. С наступлением понедельника неделя остаётся `OPEN`, но исчезает и из выбора, и из демо-запуска. Нужен запуск просроченных недель либо явный служебный механизм, который обрабатывает также текущую неделю.

5. **P2 — очередь зависает после освобождения квоты.** [sport.ts:373](/mnt/c/MGIMO/src/server/dal/sport.ts:373). Продвигается очередь только отменённого слота. Контрпример: студент получил второе занятие из очереди; другое желаемое место освободилось, пока его квота была заполнена; затем он отменил первое занятие. Теперь место свободно, квота есть, но студент продолжает ждать. Воспроизвёл на модели DAL в памяти. После отмены пересматривать доступные очереди всей недели.

6. **P2 — десять минут на переодевание фактически необязательны.** [availability.ts:25](/mnt/c/MGIMO/src/lib/sport/availability.ts:25). Пара заканчивается ровно в начале тренировки в том же корпусе — проверка возвращает разрешение: `judgeTransfer` сразу выдаёт `same-building`. Проверять запас на переодевание отдельно от времени перехода, в обе стороны.

7. **P2 — перенос пары после жеребьёвки не отражается в статусе тренировки.** [sport.ts:121](/mnt/c/MGIMO/src/server/dal/sport.ts:121), [page.tsx:94](/mnt/c/MGIMO/src/app/(cabinet)/sport/page.tsx:94). Подтверждённые записи не проверяются на актуальный конфликт и продолжают показывать «место есть» без предупреждения. Проверка выполняется только при продвижении очереди. Нужен пересчёт конфликта для своих записей с заметным предупреждением.

8. **P2 — скрытое ограничение «одно занятие в день».** [allocate.ts:77](/mnt/c/MGIMO/src/lib/sport/allocate.ts:77). Даже две разнесённые по времени тренировки со свободными местами дают только одну; вторая также исключается из ожидания. Интерфейс сообщает только квоту «два в неделю». Либо явно объявить ограничение и объяснять отказ, либо поддержать совместимость тренировок внутри дня.

9. **P2 — показанная позиция очереди не соответствует фактическому продвижению.** [sport.ts:207](/mnt/c/MGIMO/src/server/dal/sport.ts:207). Для номера учитываются квота и жеребьёвка, но пропускаются проверки расписания и второго занятия в тот же день, которые применяются при продвижении. Студент может видеть «вы первый», хотя его пропустят. Использовать одинаковую проверку доступности для номера и выдачи места.

10. **P2 — обычный `npm test` теперь захватывает интеграционные тесты без настройки.** [vitest.config.ts:6](/mnt/c/MGIMO/vitest.config.ts:6). Новые файлы подходят под `tests/**/*.test.ts`, но основной конфиг не подключает тестовую БД и заглушку `server-only`. Исключить `tests/integration/**` из модульного запуска.
