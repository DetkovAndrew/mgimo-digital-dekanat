P1 не вижу. До реализации поправил бы следующее:

1. **P2 — каскад не гарантирует прекращение push после выхода.** [push.md:28](/home/acid/projects/MGIMO/docs/plans/push.md:28). В установленном Better Auth продление сохраняет `session.id`, cookie cache выключен. Но `signOut` перехватывает ошибку удаления сессии и всё равно очищает cookie. Добавить отключение подписки при выходе; уже отправленные сообщения отозвать нельзя. `sessionId` получать сервером — нынешний `StudentContext` его не содержит.

2. **P2 — безусловный захват endpoint опасен.** [push.md:31](/home/acid/projects/MGIMO/docs/plans/push.md:31). Зная чужой endpoint, студент сможет перепривязать его и сломать доставку прежнему владельцу. Пока прежняя сессия жива, отказывать в перепривязке другой сессии. После выхода каскад освободит endpoint. Добавить проверку владельца открытого экрана, как у удаления уведомлений.

3. **P2 — конкретизировать проверку URL.** [push.md:38](/home/acid/projects/MGIMO/docs/plans/push.md:38). Разбирать через `new URL`, сравнивать `hostname` целиком либо по суффиксу **с точкой**, запретить редиректы. Указанные семейства соответствуют [FCM](https://firebase.google.com/docs/cloud-messaging/network-configuration), [Apple](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Mozilla](https://mozilla-services.github.io/autopush-rs/) и [WNS](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/push-notifications/firewall-allowlist-config). В worker проверять итоговый `new URL(url, self.location.origin).origin`: проверки `/`, но не `//`, недостаточно для пути с обратным слешем.

4. **P2 — фон оформить через `after`, не потерянный Promise.** [push.md:51](/home/acid/projects/MGIMO/docs/plans/push.md:51). После успешного коммита — `after(async () => …)` из `next/server`, перехват ошибок, ограниченная параллельность. Перед отправкой повторно проверять существование уведомления, доставку и живую сессию. Перезапуск процесса всё равно может потерять отправку — для прототипа допустимо, если уведомление остаётся в кабинете.

5. **P2 — дописать детали VAPID и смены секрета.** [push.md:47](/home/acid/projects/MGIMO/docs/plans/push.md:47). HKDF допустим, но скаляр должен удовлетворять `1 ≤ d < n`; подпись JWT — 64 байта P1363, не DER по умолчанию. После смены секрета браузерную подписку нужно пересоздать с новым `applicationServerKey`. `sub=https://…` корректен; брать доверенный адрес из конфигурации, не `Host` запроса. [RFC 8292](https://www.rfc-editor.org/rfc/rfc8292.html#section-2.1).

6. **P2 — на блокировке лучше универсальный текст.** [push.md:18](/home/acid/projects/MGIMO/docs/plans/push.md:18). Не отправлять произвольный `notification.title`: название заявки или объявления тоже может раскрывать личное. Безопасный вариант: **«University — новое уведомление» / «Откройте кабинет»**. Явно задать небольшой TTL: push-служба может хранить сообщения и доставить их после выхода. [Требования Apple](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers).

7. **P2 — добавить сценарии реального устройства.** [push.md:71](/home/acid/projects/MGIMO/docs/plans/push.md:71): выход → вход другим студентом → проверочный push; истечение сессии; смена VAPID; отправка при закрытом приложении. Service worker зарегистрировать заранее, запрос разрешения запускать непосредственно нажатием. На iOS вход из Safari и установленного приложения тоже проверить отдельно.
