# Codex 13: Ревью дизайн-токенов и тёмной темы

## Запрос

> Индексированный дифф дизайн-прохода по методике ux-ui-agent-skills: токены светлой и тёмной темы, перевод экранов на токены, `scripts/contrast.mjs`, `Disclosure`, кольцо фокуса. Запрос: пропущенные и сломанные классы, нечитаемый текст в тёмной теме, корректность WCAG и разбора CSS.

## Ответ Codex

1. **P2 — фокус исчезает у строк-ссылок.** В [ui.tsx:54](/mnt/c/MGIMO/src/components/ui.tsx:54) `overflow-hidden` обрезает внешнее кольцо `RowLink`, заданное в [globals.css:96](/mnt/c/MGIMO/src/app/globals.css:96). У списка с единственной строкой индикатор практически полностью пропадает. Для строк нужен внутренний outline либо контейнер без обрезания фокуса.

2. **P2 — фокус не виден на брендовой карточке.** На ссылке следующей пары в [today/page.tsx:51](/mnt/c/MGIMO/src/app/(cabinet)/today/page.tsx:51) кольцо совпадает с фоном в светлой теме: **1:1**; в тёмной — **2,63:1**. Нужен отдельный контрастный цвет фокуса на брендовых поверхностях и соответствующая пара в проверке.

3. **P2 — полупрозрачный текст не проходит AA в тёмной теме.** `text-on-brand/80` в [today/page.tsx:50](/mnt/c/MGIMO/src/app/(cabinet)/today/page.tsx:50) и [sport/page.tsx:118](/mnt/c/MGIMO/src/app/(cabinet)/sport/page.tsx:118) даёт **4,18:1** вместо необходимых 4,5 для этого размера текста. Убрать прозрачность либо подобрать проверенный токен; скрипт сейчас проверяет только непрозрачный `on-brand`.

4. **P2 — разбор CSS может ложно подтвердить тёмную тему.** [contrast.mjs:7–9](/mnt/c/MGIMO/scripts/contrast.mjs:7): regex зависит от пробелов и отступов, а отсутствие блока молча подменяется светлыми значениями. Проверил в памяти: допустимое `prefers-color-scheme:dark)` и одинаковые тёмные `ink`/`surface` всё равно дают **54 успешные пары**. Отсутствие блока и неподдерживаемый формат цвета должны завершать проверку ошибкой.

5. **P2 — декоративная граница используется для полей ввода.** В [request-form.tsx:8](/mnt/c/MGIMO/src/app/(cabinet)/requests/new/request-form.tsx:8) `border-hairline` — единственная граница поля на `bg-surface`; контраст около **1,26:1 / 1,30:1**. Для различимой области ввода нужен отдельный токен границы с контрастом ≥3:1; карточкам можно оставить `hairline`.

Формула WCAG корректна. К `Disclosure` замечаний нет. Проверка статическая; браузерный прогон не выполнял.
