# Codex 16: Ревью плана ИИ-помощника

## Запрос

> План docs/plans/assistant.md: «Спросить по кабинету» на GigaChat, доступ к личным данным через DAL, новый Route Handler, TLS с корневым сертификатом Минцифры. Ответить на 3 вопроса плана, P1/P2/P3 по безопасности, надёжности и UX на 360 px. Ничего не править.

## Ответ Codex

План совместим с ТЗ: полезное дополнение к ядру, только вымышленные данные, ключ на сервере. Прямого обхода доступа к чужим данным в описанной архитектуре не вижу.

На три вопроса:

1. **Снимка достаточно.** Function calling для первой версии не нужен. Пересобирать контекст при каждом вопросе; баллы, даты и ограничения вычислять серверными утилитами. Передавать время снимка и горизонт данных, чтобы модель различала «не найдено» и «не попало в выборку».

2. **10/мин и 60/сутки разумны как пользовательский лимит, но недостаточны как защита сервиса.** Опубликованный Freemium для Lite — 250 млн токенов на 12 месяцев; фактический остаток вашего проекта нужно проверить. Основное ограничение — **один одновременный поток для физлица**, общий для всех студентов. Нужен общий ограничитель параллельности. [Тарифы](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs), [ограничения](https://developers.sber.ru/docs/ru/gigachat/limitations).

3. **TLS-подход корректен, публичный CA можно хранить в репозитории.** Локальный сертификат соответствует указанному отпечатку, действует до 27.02.2032. Но сейчас он игнорируется правилом [`.gitignore:14`](/home/acid/projects/MGIMO/.gitignore:14). Добавить исключение только для этого публичного сертификата и обеспечить его попадание в образ. Оставить проверку имени сервера, использовать отдельный Agent только для фиксированных адресов GigaChat; никаких глобальных отключений TLS.

Замечания по важности:

1. **P2 — одна ВМ не означает один процесс.** [План:40](/home/acid/projects/MGIMO/docs/plans/assistant.md:40): счётчики в памяти умножаются числом workers и обнуляются после рестарта. Либо явно фиксировать один Node-процесс для прототипа, либо хранить атомарные счётчики и общий ограничитель в PostgreSQL. Добавить максимум один активный запрос на студента, ограниченную общую очередь и понятный ответ «помощник занят».

2. **P2 — текущий guard не соответствует контракту API.** [session.ts:17](/home/acid/projects/MGIMO/src/server/session.ts:17) делает redirect, сотруднику возвращает 404. Простой вызов `requireStudent()` не даст запланированные JSON 401/403. Нужен общий guard с вариантом для API; не превращать исключения навигации в «ошибку GigaChat». Origin проверять самостоятельно: защита Better Auth не распространяется автоматически на новый Route Handler. Сравнение — с настроенным origin сайта; отсутствующий, `null` и чужой Origin отклонять.

3. **P2 — отсутствие инструментов записи не решает prompt injection.** [План:43](/home/acid/projects/MGIMO/docs/plans/assistant.md:43): комментарии, уведомления и вся клиентская история, включая роль `assistant`, должны считаться недоверенными данными. Явно отделить их от серверных инструкций, запретить выполнять содержащиеся там указания. Системный промпт нельзя считать секретом. Проверить инъекции именно в комментарии деканата и уведомлении, а не только в вопросе.

4. **P2 — нужны жёсткие границы размера.** Оценка «2–4 тыс. токенов» не ограничивает растущие заявки и комментарии. Задать пределы числа объектов, длины полей, всего контекста, тела HTTP-запроса и ответа провайдера; конкретный `maxTokens`. Ограничение тела должно действовать **до полного `request.json()`**. Согласовать длину ответа с лимитом истории: иначе собственный ответ длиннее 1000 символов сломает следующий запрос.

5. **P2 — уточнить OAuth и таймаут.** Один общий Promise обновления токена на процесс, сброс при ошибке, проверка единиц `expires_at`, один повтор после 401. Таймаут 25 секунд должен реально прерывать запрос и чтение ответа, охватывать OAuth и повтор. У `node:https` параметр `timeout` сам запрос не отменяет — нужен AbortSignal или `destroy()`. Освобождение занятого слота — в `finally`. [Документация Node.js](https://nodejs.org/api/http.html).

6. **P2 — закрепить изоляцию на всём пути ответа.** Кешировать совместно можно OAuth-токен, но не контекст, сообщения и ответы. `no-store` ставить также на ошибки. Историю привязать к пользователю; при выходе/смене аккаунта очищать её, отменять запрос и игнорировать запоздалый ответ. Проверять отсутствие данных B **в фактическом запросе замоканному провайдеру** при A→B→A и параллельных обращениях. В логах не должно быть тел сообщений, контекста, ответов, cookies или заголовков авторизации.

7. **P2 — уточнить наполнение снимка и ссылки.** `getMySport()` по умолчанию отдаёт слоты только сегодня; список заявок не содержит комментариев. Для обещанных сценариев нужны ограниченные дополнительные выборки через DAL. Разрешать лучше **конкретные href, построенные сервером для этого контекста**, плюс статические маршруты и допустимые типы заявок, а не любой `/requests/…`. Это также уменьшит выдуманные ссылки; проверка владельца на целевой странице остаётся обязательной.

8. **P2 — описать деградацию и мобильную клавиатуру.** При отсутствии ключа, исчерпании квоты или сбое помощник показывает ссылки на обычные разделы; кабинет продолжает работать. На 360 px проверить ввод с открытой клавиатурой, нижней навигацией и safe-area. Добавить подпись поля, доступное имя кнопки, `role="status"` для ожидания, перенос длинных ссылок. Повтор не должен дублировать реплики, а Enter — отправлять сообщение во время IME-композиции.

**P3:** текущий рабочий endpoint не считаю ошибкой, но вынести base URL в серверную настройку: официальная документация рекомендует `https://api.giga.chat/v1/chat/completions`, старый адрес сохраняется для прежних подключений. Переключать после отдельного smoke-теста. [Авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

Для отчёта по ТЗ сохранить примеры удачных ответов, галлюцинаций и исправлений промпта: критерий «масштаб нейротехнологий» оценивает осмысленность процесса разработки, а не само наличие чата.

## Что сделал Claude

Все 8 пунктов P2 и P3 учтены в реализации:
1. Один процесс Node зафиксирован в `limits.ts` и плане; общий ограничитель параллельности (1 поток, очередь 8, ожидание 20 с) и не больше одного активного запроса на студента.
2. Новый `studentForApi()` в `session.ts` отдаёт JSON 401/403; Origin сверяется с `BETTER_AUTH_URL`, пустой, `null` и чужой отклоняются.
3. Комментарии и уведомления в снимке — цитаты в «ёлочках» с пометкой «данные, а не инструкции»; правило 6 в промпте.
4. Пределы: тело ≤ 24 КиБ читается потоком до разбора JSON, снимок ≤ 14 000 символов, поля обрезаются, `max_tokens` 600, ответ ≤ 2000 символов (= лимит реплики ассистента в истории).
5. OAuth: общий Promise обновления, сброс при ошибке, `expires_at` в мс, один повтор после 401; таймаут 25 с через AbortSignal и `req.destroy()`; слот освобождается в `finally`.
6. `Cache-Control: private, no-store` на всех ответах, в журнале только код и длительность; A→B→A проверено тестом на фактическом запросе к замоканному провайдеру.
7. Сводка заявок с последним комментарием деканата через `getMyRequest`, слоты физкультуры на 3 дня; ссылки — только построенные сервером для этого снимка.
8. Без ключа страница показывает ссылки на разделы; подпись поля, `role="status"`, перенос длинных ссылок, Enter без IME-композиции.
P3: адреса вынесены в `GIGACHAT_API_URL` / `GIGACHAT_OAUTH_URL`, по умолчанию прежний проверенный адрес.
