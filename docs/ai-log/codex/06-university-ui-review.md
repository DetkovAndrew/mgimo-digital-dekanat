## Ответ Codex

1. **P1 — карточка следующей пары становится нечитаемой.** [today/page.tsx:51](/mnt/c/MGIMO/src/app/(cabinet)/today/page.tsx:51): `Card` добавляет `bg-white`, который в сгенерированном Tailwind CSS перекрывает `bg-brand`. При `!text-white` получается белый текст на белом фоне. Подтверждено компиляцией CSS в памяти. Использовать `!bg-brand` либо убрать конфликт через вариант компонента.

2. **P2 — неоценённые точки считаются доступными для добора независимо от срока.** [grading.ts:46](/mnt/c/MGIMO/src/lib/grading.ts:46), [grades/page.tsx:67](/mnt/c/MGIMO/src/app/(cabinet)/grades/page.tsx:67): просроченная работа и работа, ожидающая проверки, попадают в `remaining`, но отсутствуют в знаменателе «возможных на сегодня». Например, единственные оценённые 10/10 дают прогноз A даже при остальных просроченных точках. Разделить доступные, просроченные и ожидающие проверки; знаменатель подписать как максимум **оценённых** точек.

3. **P2 — обычному зачёту показывается числовая оценка.** [grades/page.tsx:43](/mnt/c/MGIMO/src/app/(cabinet)/grades/page.tsx:43): ветки с оценкой и прогнозом одинаковы для `CREDIT` и экзаменов. Студент видит «прогноз A · 5» по недифференцированному зачёту. Для `CREDIT` показывать прогноз достижения порога; подтверждённый результат брать из `passed`.

4. **P2 — прошлый семестр показывает первую контрольную точку вместо итога.** [grades/page.tsx:111](/mnt/c/MGIMO/src/app/(cabinet)/grades/page.tsx:111): `o.assessments[0]` при наличии промежуточных тестов окажется ранним тестом. После появления следующего семестра накопленные баллы и итог текущего будут отображаться неправильно. Находить итоговую аттестацию по `controlForm` и отдельно рассчитывать сумму контрольных точек.

5. **P2 — «ближайшая возможность» выбирается не по ближайшей дате.** [grades/page.tsx:24](/mnt/c/MGIMO/src/app/(cabinet)/grades/page.tsx:24): `.find()` использует порядок DAL — сначала `scheduledAt`, затем `dueAt`. Поэтому тест 20 ноября оказывается раньше лабораторной со сроком 11 ноября. Сначала сортировать по единой эффективной дате.

6. **P2 — DAL может вернуть срок вне запрошенного интервала.** [grades.ts:56](/mnt/c/MGIMO/src/server/dal/grades.ts:56), [grades.ts:76](/mnt/c/MGIMO/src/server/dal/grades.ts:76): фильтр допускает совпадение по любой дате, а результат всегда предпочитает `dueAt`. При `scheduledAt` внутри интервала и `dueAt` снаружи возвращается неправильный срок. Фильтровать и сортировать по одному правилу выбора даты; для fallback на `scheduledAt` проверять `dueAt: null`.

7. **P2 — онлайн-занятие с сохранённым корпусом создаёт ложный переход.** [transfers.ts:20](/mnt/c/MGIMO/src/lib/transfers.ts:20): поле `online` отсутствует даже в `LessonLike`; фильтрация проверяет только корпус. Воспроизводится ложное «не успеть» для онлайн-пары с `building`. Добавить `online` и исключать такие занятия явно.

8. **P2 — прошедшие переходы продолжают требовать действия.** [today/page.tsx:40](/mnt/c/MGIMO/src/app/(cabinet)/today/page.tsx:40): предупреждения собираются за весь день. Вечером остаётся «Сегодня не успеть» про утренние пары. Сохранить время целевой пары в `Transfer` и исключать завершённые переходы из блока внимания.

9. **P3 — недостаточный размер мобильной цели касания.** [lesson-card.tsx:52](/mnt/c/MGIMO/src/components/lesson-card.tsx:52): `min-h-9` гарантирует только 36 px вместо требуемых проектом 44 px. Заменить на `min-h-11`.
