# Codex 10: Ревью плана раскрытия

## Запрос

> План `docs/plans/drilldown.md`: страницы пары, дисциплины, преподавателя и корпуса; прогнозы по баллам убрать. Запрос: безопасность и 404, Next.js 16, UX на 360 px, лишнее для срока 20.11.

## Ответ Codex

1. **P1 — уточнить границу публичности.** В [плане:13](/mnt/c/MGIMO/docs/plans/drilldown.md:13) доступ преподавателя и корпуса допустим любому **вошедшему студенту**. Отсутствие своих занятий → пустой список, не 404. Чужая пара/дисциплина → 404; преподаватель чужой группы → разрешённый публичный набор полей. Не отдавать историю переносов и её комментарии через публичное расписание. Это исключение из ограничения расписания своей группой стоит закрепить в правилах проекта.

2. **P1 — добавить третьего студента в тесты.** [Пары A/B разных групп недостаточно](/mnt/c/MGIMO/docs/plans/drilldown.md:53): нужен C **той же группы, что A**, с другими оценками и бронями. Проверить результаты, попытки, комментарии и тренировки A/C; анонимный доступ; разрешённое открытие чужого преподавателя; пустой существующий корпус; состав вложенных объектов публичного ответа.

3. **P1 — страницы преподавателя и корпуса тоже персонализированы.** `mine`, «ведёт у вас» и «мои занятия» зависят от сессии. Не помещать целый результат DAL в `unstable_cache`/`use cache` по одному ID. Текущий React `cache` для guards подходит. Добавить проверку A → выход → B → возврат браузером, включая ранее открытые подробности.

4. **P1 — универсальные ссылки сломают тренировки.** [schedule.ts:79](/mnt/c/MGIMO/src/server/dal/schedule.ts:79) возвращает синтетический `sport-${bookingId}`, для которого `/lessons/[id]` даст 404. Уже сейчас нужен выбор ссылки по `source`: учебная пара → подробности пары; тренировка → `/sport` до появления отдельной страницы. Тренер пока строка, ссылки на `Teacher` у него нет.

5. **P2 — «зачтено» нельзя выводить из суммы баллов.** В [плане:27](/mnt/c/MGIMO/docs/plans/drilldown.md:27) разделить «набрано 64, порог пройден» и официальный результат аттестации `passed/grade`. При 30 баллах посреди семестра не показывать фактическую двойку из текущего диапазона. Сохранить различия зачёта, экзамена и зачёта с оценкой, последние попытки и даты сессии.

6. **P2 — убрать прогноз, сохранить конкретный сигнал проблемы.** Вместо полного [удаления `passReachable`](/mnt/c/MGIMO/docs/plans/drilldown.md:36) оставить `до 60 ещё N` и проверку: даже с максимумом оставшихся и неоценённых работ порог недостижим → «Обсудите добор с преподавателем». Это арифметика, не прогноз. Не удалять тесты суммирования, нулевых баллов и достижимости вместе с тестами темпа.

7. **P2 — вложенные ссылки остаются в главной карточке.** [План:32](/mnt/c/MGIMO/docs/plans/drilldown.md:32) одновременно делает её ссылкой и сохраняет ссылку маршрута. Оставить контейнер обычным: заголовок/основная область → пара, отдельная кнопка → карты. Без вложенного `<a>` и контейнера с `onClick`, перехватывающего кнопку.

8. **P2 — явно записать контракт Next.js 16.** `await params` и `await searchParams`, включая `generateMetadata`; проверку владельца выполнять через тот же DAL. `notFound()` бросает исключение — не поглощать общим `catch`. После начала streaming страница ошибки может иметь HTTP 200: проверять настоящий HTTP-статус чужого объекта, а не только исключение в DAL, и выполнять проверку доступа до streaming-границы.

9. **P2 — у `router.back()` нет встроенного fallback.** [План:41](/mnt/c/MGIMO/docs/plans/drilldown.md:41) требует уточнения: `history.length > 1` не доказывает, что предыдущая страница принадлежит кабинету. Для прототипа проще постоянная ссылка «К расписанию»/«К учёбе» с сохранением недели. Настоящий «Назад» — только при известном внутреннем переходе; иначе запасной `href`.

10. **P2 — добавить идентификаторы в существующие DTO.** Сейчас [schedule.ts:21](/mnt/c/MGIMO/src/server/dal/schedule.ts:21) не возвращает `offeringId` и ID фактического преподавателя, а [grades.ts:69](/mnt/c/MGIMO/src/server/dal/grades.ts:69) — offering для ссылки дедлайна. Добавить их через `select`, без дополнительных запросов на каждую карточку. Формула подмены преподавателя в плане верна; протестировать явную подмену и fallback на ведущего.

11. **P2 — раскрытие не должно прятать важное.** В списке оставить не только «Изменено», но короткое «перенесено на 17:00»/«другой корпус». На странице пары сначала актуальные время, место и маршрут; история — свёрнута. Для недель преподавателя/корпуса валидировать дату и ограничить диапазон, считать границы по Москве. На 360 px — список, не недельная сетка; сохранить контекст недели при возврате.

12. **P3 — сократить объём до 20.11.** Приоритет: пара → дисциплина → компактные страницы преподавателя и корпуса. Полную историю хранить, но показывать по раскрытию. Первым кандидатом на отсрочку считаю просмотр произвольных недель преподавателя: текущей недели достаточно. Новые поля биографии, контакты, редакторы справочников и объединение тренера с `Teacher` этому шагу не нужны.
