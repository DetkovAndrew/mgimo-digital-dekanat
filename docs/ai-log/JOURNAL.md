**9. База данных и авторизация (Claude Code).**
- Версии закреплены точно (`--save-exact`). Тег `latest` у Prisma указывал на 8.0.0-rc.
  Claude это заметил и поставил стабильную 7.10.1: Better Auth официально поддерживает Prisma 7.
- npm 11 блокирует установочные скрипты пакетов. Claude прочитал их код и только потом
  разрешил четыре скрипта: ссылки бинарников PostgreSQL, движки Prisma, esbuild.
  Список разрешённых скриптов хранится в `package.json` (`allowScripts`).
- `scripts/db.ts` поднимает PostgreSQL 18 на `127.0.0.1:54329` и создаёт базы dev, shadow и test.
  - **Ошибка, которую предсказал Codex, подтвердилась:** PostgreSQL отказался запускаться
    на DrvFS («data directory has invalid permissions»). `chmod` там проходит,
    но биты прав не сохраняются.
  - Решение: перенесён только каталог данных БД в `~/.local/share`.
    Проект и `node_modules` остались на C:, как требует инструкция среды.
- `.env.example` без секретов. В `.env` пароль БД и `BETTER_AUTH_SECRET` сгенерированы
  `openssl rand`, никто их не видел и не вводил.
- `prisma init` неожиданно добавил 11 навыков для ИИ-агентов в трёх копиях (Claude, Codex, Windsurf).
  Claude просмотрел их как сторонние инструкции: нет ли команд скачивания, удаления, ключей.
  Оставлены три, относящиеся к нашему стеку. Копия для Windsurf удалена.
- `prisma init` создал конфиг с `dotenv`, которого нет в проекте. Заменено на встроенный
  `process.loadEnvFile`.
- Better Auth: старый CLI `@better-auth/cli` объявлен устаревшим. Claude нашёл новый пакет `auth`
  той же версии и сгенерировал им таблицы.
  - Решения: вход по логину, регистрация отключена, роль нельзя задать с клиента,
    лимит 5 попыток входа в минуту.
- Предметная модель: 15 моделей. Это набросок Codex плюс таблица преподавателей,
  номер заявки и `timestamptz`. Перед миграцией схема отправлена на ревью Codex.

**10. Ревью схемы и авторизации (Codex 03)** → [codex/03-schema-auth-review.md](codex/03-schema-auth-review.md).
Codex нашёл две ошибки до того, как они проявились бы в работе:
- **seed упал бы:** `disableSignUp` запрещает и серверный `signUpEmail`.
  Решение: отдельный экземпляр Better Auth только внутри seed.
- **Лимит попыток входа обходился бы:** вход через Server Action с прямым `auth.api`
  проходит мимо ограничителя. Решение: вход через HTTP-клиент Better Auth.
- Также: история переноса хранит полный переход «было → стало», номер заявки — `autoincrement`
  (не `count()+1`), SQL `CHECK` на оценки и даты, индексы.
  Guards сами загружают `studentId` из БД, ESLint запрещает импорт Prisma вне `src/server`.
- Claude добавил сверх ревью справочник факультетов: это граница доступа сотрудника деканата.

**11. Проверка правок (Codex 04)** → [codex/04-review-fixes-check.md](codex/04-review-fixes-check.md).

**12. Seed с вымышленными данными (Claude Code).** 3 аккаунта: 2 студента разных факультетов

**14. Простая веб-панель (запрос команды).** Вход, «Сегодня», расписание по неделям, учёба,
заявки (каталог → форма → статус и история, отзыв, ответ на уточнение), уведомления, профиль,
заглушка кабинета сотрудника. Слой доступа (`src/server/dal/*`) сам вызывает guard и фильтрует по владельцу.
- Требование команды: только `127.0.0.1:3000`, ничего наружу. `next dev -H 127.0.0.1`,
  `BETTER_AUTH_URL` переведён на 127.0.0.1, иначе проверка origin отклоняла бы вход.
- Ошибки по ходу работы:
  - Claude забыл создать папки маршрутов, две страницы не записались — пересоздал.
  - Генератор включил `cacheComponents`, и личные страницы падали на `new Date()` при пререндере.
    Режим выключен: личное не должно попадать в кеш.
  - Ошибка в тесте самого Claude: вход с неверным паролем перезаписал файл cookies студента A.
- Проверка curl:
  - вход A/B/сотрудника — 200, неверный пароль — 401, шестая попытка за минуту — 429;
  - A → заявка B — **404**;
  - сотрудник → кабинет студента — 404, студент → `/staff` — 404.
- Открыть в защищённом Firefox не удалось: служба браузера получила ссылку,
  но Firefox не открыл дисплей (`cannot open display: :0`). Сообщено команде, среду Claude не менял.
