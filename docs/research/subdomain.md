### Ограничения, которые учитываем

- DuckDNS **не обещает бесперебойную и безошибочную работу**, а условия допускают
  приостановку аккаунта с уведомлением или без него [8]. Это дополнительная внешняя
  зависимость; для короткого демо её можно принять, гарантировать доступность нельзя.
- Это поддомен чужой зоны: у нас управление записью в DuckDNS, а не владение `duckdns.org`.
  При переходе на другого DNS-провайдера понадобится другое имя.
- Доступ из российских сетей и конкретный VPS проверяются отдельно: имя не снимает
  ограничения маршрута до сервера. Такую проверку из текущей среды не подтверждаем.
- Нужен актуальный IP: при смене IP обновить запись; автоматическое определение
  может указать адрес домашней сети вместо VPS. Токен DuckDNS хранить как секрет [2].
- HTTPS настраивается отдельно. Для обычного HTTP-01 нужен доступный порт 80;
  иначе можно использовать DNS-01 с TXT-записью DuckDNS [2, 7]. Сертификат и его
  автоматическое продление проверить до передачи ссылки жюри.

Для снижения риска до сдачи проверить ссылку с двух сетей; если найдутся проблемы,
выбрать собственный `.ru` и повторить проверки. Резервный адрес требует собственного
сертификата и корректной настройки адреса приложения; простой дубликат имени не
гарантирует работу входа. Не выдаём текущую работоспособность страницы DuckDNS
за проверку будущего прототипа.

**Для бесплатного варианта — DuckDNS.** Получаем постоянное читаемое имя
`<выбранное-имя>.duckdns.org`, затем направляем его на публичный IP выбранного VPS.
При смене VPS можно обновить IP, сохранив адрес. Это DNS-сервис; само приложение
и PostgreSQL по-прежнему нужно разместить на работающем сервере [1, 2].

Выбран и зарегистрирован `university-dekanat`. Запасной вариант `dekanat-demo-2026`
не проверялся и не регистрировался.
В названии не используем официальный бренд или утверждение об официальном сервисе вуза.

## Сравнение

| Вариант | Цена имени | Что потребуется | Когда выбирать |
|---|---|---|---|
| DuckDNS: `<имя>.duckdns.org` | Бесплатно | Вход в сервис, свободное имя, позднее IP VPS; HTTPS настраивается отдельно | Основной бесплатный вариант с читаемым адресом [1, 2] |
| sslip.io / nip.io: `<имя>.<ip>.sslip.io` | Бесплатный публичный DNS-сервис | Публичный IP; имя сразу вычисляется из адреса, отдельная регистрация имени не нужна | Быстрая техническая демонстрация; при смене IP меняется и этот адрес [3] |
| Собственный `.ru` | На витрине Timeweb **200 ₽ за первый год**, продление **399 ₽/год** | Свободное имя, регистрация владельца/подтверждение данных и оплата; A-запись на VPS | Если хочется короткого собственного адреса и управления DNS. Итоговую цену подтвердить до оплаты [4] |
| Поддомен уже имеющегося домена | Обычно без отдельной платы за регистрацию поддомена | Доступ к DNS действующего домена | Проверить позже, когда будем обсуждать инфраструктуру капитана; сейчас не зависит от этого варианта |
| Технический домен Timeweb Cloud | Бесплатно для сервиса в их панели | Привязка к сервису Timeweb | Для стороннего UK-VPS не подходит: стороннюю A-запись поставить нельзя. Документация также запрещает заказ SSL-сертификата для него через их сервис [5]. Это не доказательство невозможности любого стороннего ACME-сертификата. |

Цены проверены 11.11, это рекламная витрина, а не выставленный счёт.
Домен `.ru` регистрируется минимум на год; отдельный оплаченный хостинг Timeweb
для использования своего домена с другим VPS не требуется. Перед заказом убрать
ненужные дополнительные услуги и проверить окончательный состав покупки.

## Что нужно сделать для бесплатной схемы

1. Выбрать название и войти на [DuckDNS](https://www.duckdns.org/).
   Человек проходит вход под своим аккаунтом; общий токен управления не публикуется в Git.
2. Добавить свободное имя. Привязку к серверу выполнить, когда будет известен его
   публичный IP. Не принимать автоматически определённый домашний IP за IP VPS:
   в документации API явно указано, что при пропуске IP он определяется из запроса [2].
3. На сервере настроить Nginx и сертификат Let's Encrypt через Certbot.
   Для стандартной проверки HTTP-01 домен должен вести на сервер, а порт 80
   должен быть доступен извне; HTTPS обслуживается на 443 [6, 7].
4. Настроить автоматическое продление сертификата. `BETTER_AUTH_URL` в окружении
   приложения должен совпадать с итоговым HTTPS-адресом; секреты не отправлять в браузер.
5. Проверить вход двух студентов, заявку, перезаход и доступ по HTTPS с домашней
   и мобильной сети в РФ без VPN. Адрес не меняет сетевую доступность самого VPS.

Имя уже создано. Реальное подключение и проверка HTTPS требуют публичного IP
сервера и доступа к нему; эти сведения пока не предоставлены.
Наличие доступной главной страницы DNS-провайдера не считается проверкой
работоспособности нашего будущего сайта из России.
