# Проверка кабинета на телефонах

Срок: 18–19.11.2026 после переделки «Сегодня», «Учёба», «Спорт».
**Этот документ — протокол; наличие строки не означает успешного теста.**
Проверки текущей локальной сборки — в [local-checks.md](local-checks.md).

## Окружение и доказательства

Зафиксировать URL, commit/версию, дату seed, время МСК, устройство, ОС, браузер и версию,
ширину viewport, сеть и оператора, включён ли VPN. Пароли вводить до начала записи экрана.
Два студента: Алина / Тимур; после каждой смены аккаунта проверить ФИО в профиле.

| Устройство / среда | Результат | Дата / версия / доказательство |
|---|---|---|
| Desktop, viewport 360 px | Не проверено по всему сценарию | — |
| Android, реальный телефон | Не проверено | — |
| iPhone / Safari, реальный телефон | Не проверено | — |
| Desktop ≥1280 px | Не проверено по всему сценарию | — |

Если iPhone недоступен, написать «не проверено» и привлечь знакомого с устройством.
Эмуляция ширины не заменяет проверку экранной клавиатуры и Safari на телефоне.

## Основной сценарий — повторить для каждого студента

| № | Действие | Ожидаемое поведение |
|---|---|---|
| 1 | Войти; ошибиться паролем один раз, затем ввести верный | Понятная ошибка без утечки; успешный вход под нужным студентом. Дисклеймер виден. |
| 2 | Открыть профиль | Свои ФИО, факультет, направление, курс и группа. |
| 3 | «Сегодня» → расписание дня/недели → пара | Время МСК, аудитория, преподаватель, выделенный перенос или отмена. Назад возвращает к понятному контексту. |
| 4 | Открыть корпус и «Маршрут» | Корректный корпус и адрес; Яндекс Карты открываются по ссылке. Онлайн-пара не требует поездки. |
| 5 | «Учёба» → дисциплина → предыдущий семестр | Свои баллы, дефицит до 60, ближайшая работа и дата; попытки не суммируются, итог не подменён текущей суммой. |
| 6 | «Заявки» → справка об обучении | Подписи полей видны; пустые/неверные значения объяснены; экранная клавиатура не закрывает кнопку. |
| 7 | Отправить с вымышленным назначением «По месту требования (демо)» | Одна заявка с номером и статусом; быстрый повторный клик не создаёт неожиданный дубль. |
| 8 | Обновить страницу → выйти → снова войти | Заявка с тем же номером и статусом сохранилась. |
| 9 | Уведомления → своё уведомление → «прочитано» | Счётчик изменился, состояние сохранилось после обновления. Будущих уведомлений нет. |
| 10 | Спорт: подходящий слот → запись/приоритет → результат | Зафиксировать актуальный механизм. Подтверждение не путается с очередью или приоритетом. Бронь видна в расписании. |
| 11 | Спорт: конфликт/нет мест/квота → отмена своей записи | Понятная причина; невозможная запись не создаётся; отмена и состояние расписания согласованы. |
| 12 | Выйти из A → войти в B в той же вкладке | Ни имени, ни заявок, ни оценок, ни уведомлений A у B. Проверить кнопку «Назад» и обновление. |

Остановку/перезапуск сервера для проверки сохранности проводит разработчик;
не запускать `db:seed` между созданием заявки и проверкой её сохранности.

## Дополнительные проверки 360 px

- Нет горизонтальной прокрутки; длинное название предмета и длинное сообщение не ломают карточки.
- Нижнее меню, дисклеймер и кнопки не перекрывают контент; последний пункт страницы достижим.
- Управление доступно касанием, основные цели ≥44 px. Масштаб текста 200% остаётся пригодным.
- На desktop пройти Tab/Shift+Tab/Enter: видимый фокус, подписи и понятные имена ссылок.
- Медленная сеть/нет сети: понятное состояние ожидания/ошибки, повтор не удваивает отправку.
- Прямой URL чужой пары/дисциплины/заявки → 404; без входа → вход.
  UUID брать только с тестового стенда. Нельзя считать скрытую кнопку защитой.
