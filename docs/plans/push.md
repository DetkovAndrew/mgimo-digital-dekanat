# Уведомления на телефон (web push)

Капитан, 21.11: «сделать чтобы при добавлении на экран смартфона как ссылка на сайт были и уведомления». Бот в
мессенджере — нет. Решение принято за день до сдачи, поэтому объём минимальный и всё за флагом «студент включил сам».

## Что получает студент

Профиль → блок **«Уведомления на телефон»** (только студент). Состояния:

| Состояние | Что видно |
|---|---|
| Браузер не умеет push (нет `serviceWorker` / `PushManager`) | «Этот браузер не присылает уведомления» |
| iPhone/iPad, сайт открыт не с экрана «Домой» | «Поделиться → На экран „Домой“, затем откройте University с иконки» (push на iOS 16.4+ только у установленного сайта) |
| Разрешение отклонено | как включить в настройках браузера |
| Выключено | кнопка «Включить» → запрос разрешения → подписка → «Включено на этом устройстве» |
| Включено | «Проверить» (проверочное уведомление) и «Выключить» |

Push приходит на каждое новое уведомление кабинета этому студенту: статус заявки, перенос/отмена/возврат пары
деканатом, объявление деканата, место из очереди на физкультуру. На экране блокировки — **только тип события**
(«Изменение в расписании», «Новый статус заявки», «Новое уведомление») и «Откройте кабинет University»: заголовок
уведомления может раскрыть личное — название справки, текст объявления (ревью Codex 98). Нажатие открывает ссылку
уведомления (заявка / неделя пары / `/notifications`).

## Данные

Таблица `push_subscription`: `id`, `userId` → user (cascade), **`sessionId` → session (cascade)**, `endpoint` (unique),
`p256dh`, `auth`, `createdAt`.

- Подписка привязана к **сессии**, а не только к пользователю. Выход удаляет сессию (Better Auth) → подписка удаляется
  каскадом: после выхода телефон больше не получает уведомления прежнего аккаунта. Истёкшая сессия (`expiresAt < now`)
  — не шлём.
- `endpoint` unique. Подписку **другой живой сессии** не перехватываем — отказ (зная чужой адрес, иначе можно забрать
  чужие уведомления). После выхода или истечения той сессии адрес свободен (ревью Codex 98).
- Перед выходом (`SignOut`) браузер отвязывает устройство (`releaseMyDevice`, только текущая сессия) и отписывается:
  Better Auth глотает ошибку удаления сессии при выходе, каскад одного его не гарантирует.
- У всех действий `owner` — для кого открыт экран; другой аккаунт в соседней вкладке → «обновите страницу».
- Не больше 20 подписок на пользователя (демо-аккаунты общие для жюри): сверх — удаляется самая старая.
- Владелец — только из сессии; `endpoint`/ключи — из тела запроса, проверяются zod.

## Защита

- **SSRF:** сервер делает POST на `endpoint` из запроса студента. Допускаем только `https:` и хосты служб push:
  `fcm.googleapis.com`, `*.push.apple.com`, `*.push.services.mozilla.com`, `*.notify.windows.com`, без порта, без
  userinfo, длина ≤ 1024. Остальное — отказ при подписке (и повторная проверка при отправке).
- Ключи: `p256dh` — base64url, 65 байт, первый 0x04 и точка на кривой P-256 (проверяет `createECDH().computeSecret`);
  `auth` — base64url 16 байт.
- **Проверочное** — только на endpoint своей текущей сессии (не всем устройствам общего аккаунта), не чаще раза в 30 с
  на пользователя (счётчик в памяти, один процесс Node).
- Шифрование содержимого — RFC 8291 (aes128gcm), службы Google/Apple видят только шифротекст. Подпись — VAPID
  (RFC 8292, ES256 JWT: `aud` — origin endpoint, `exp` +12 ч, `sub` — адрес сайта).
- Ключ VAPID выводится из `BETTER_AUTH_SECRET` (HKDF «univ-webpush-v1:i» → скаляр P-256, берётся первый в [1, n)),
  как у пропуска, Wi-Fi и календаря: новой переменной окружения на сервере нет. Подпись JWT — 64 байта P1363.
  Публичный ключ отдаётся клиенту; после смены секрета профиль видит другой ключ у подписки браузера и пересоздаёт её.
- TTL — 1 час: служба не держит сообщение долго и не «догоняет» устройство после выхода.
- Библиотека `web-push` — MPL-2.0, не из разрешённых лицензий: шифрование и JWT на `node:crypto`, ~150 строк, тест по
  вектору из приложения A RFC 8291.
- Отправка — **после** коммита транзакции через `after()` из `next/server` (не задерживает действие сотрудника),
  по одной, таймаут 10 с, без редиректов. При отправке всё перечитывается: уведомление (могли отозвать), получатели без
  `hiddenAt`, живые сессии. 404/410 от службы → подписка удаляется. Перезапуск процесса может потерять отправку —
  уведомление остаётся в кабинете. В журнал не пишем endpoint, заголовки и текст — только счётчики ошибок.
- Service worker `public/sw.js`: `push` → `showNotification(title, { body, icon, tag, data: { url } })`;
  `notificationclick` → открыть/сфокусировать **только страницу того же сайта**: `new URL(url, origin).origin === origin`
  (путь «/\\evil» и «//evil» браузер понял бы как чужой адрес).

## Код

- `src/server/push/webpush.ts` — VAPID-ключ, JWT, шифрование aes128gcm, `send(sub, payload)`.
- `src/server/dal/push.ts` — `subscribeMyDevice`, `unsubscribeMyDevice`, `sendMyTestPush` (студент из сессии),
  `pushNotification(id)` — получатели по `notification_recipient`, ссылка как в списке уведомлений.
- Точки вызова: `staff.ts` (статус заявки), `staff-schedule.ts` (перенос/отмена/возврат), `staff-announcements.ts`,
  `sport.ts` (очередь) — id созданного уведомления возвращается из транзакции, `pushNotification` после неё.
- Профиль: клиентский компонент `push-toggle.tsx` + Server Actions.

## Проверки

- Модульные: шифрование по вектору RFC 8291, JWT (подпись проверяется публичным ключом), фильтр endpoint, ключи.
- Интеграционные (A/B): подписка пишет владельца из сессии; чужой endpoint перехватывается на свою сессию, но
  отписка/проверочное по чужому endpoint — отказ; выход (удаление сессии) удаляет подписку; лимит 20;
  `pushNotification` выбирает только подписки получателей и живых сессий.
- Вручную (капитан, на живом сайте): Android Chrome; iPhone — из Safari (подсказка «На экран „Домой“») и с иконки;
  выход → вход другим студентом → проверочное не приходит прежнему; приложение закрыто — push всё равно приходит.

## Что проверено 21.11

- Шифрование совпало байт в байт с примером RFC 8291 (тест `webpush.test.ts`).
- Подпись VAPID принимают настоящие службы: на фальшивый токен с нашей подписью FCM отвечает 410, Apple —
  `BadDeviceToken`; с испорченной подписью — 403 `invalid JWT` / `BadJwtToken`.
- Интерфейс в headless Chromium: «выключены», «запрещены», подсказка iPhone; подписка там невозможна (нет службы push)
  — показывается ошибка. Полный путь до телефона здесь не проверить: Firefox Playwright не подключился к autopush.
