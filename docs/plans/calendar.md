# Календарь, контакты и печать расписания

Капитан, 18.11: «выгрузка в календарь для айфон („Добавить в календарь“). Расписание и т. д. И в целом над другими
выгрузками подумать». Решения капитана: подписка + файл; ещё — одно событие в календарь, контакты служб (.vcf),
расписание на печать. «Скачать все мои данные» — нет (JSON мало кому удобен).

## Что получает студент

Экран **«Календарь и печать»** (`/schedule/export`, ссылка из шапки расписания и из профиля):

1. **Подписаться** — «Добавить в Календарь iPhone» (`webcal://…`), «Google Календарь» (ссылка `calendar.google.com/…?cid=`),
   адрес для копирования (Outlook, Android). Календарь телефона сам обновляет подписку: перенос пары деканатом
   приходит в календарь без входа в кабинет.
2. **Скачать файл** — неделя или весь семестр с сессией (`.ics`, разовый снимок).
3. **Распечатать** — неделя или сессия на A4 (страница для печати; «Сохранить как PDF» — средствами браузера, на iPhone
   «Поделиться → Напечатать»).
4. **Выпустить новую ссылку подписки** — старая перестаёт работать.

Плюс кнопка **«В календарь»** у одного события: пара, экзамен/зачёт, срок работы, тренировка, бронь аудитории.
**«В контакты»** у каждой службы в «Куда обратиться» (`.vcf`: название, почта, адрес, часы).

## Что в календаре

Диапазон: 14 дней назад — конец сессии текущего семестра (не больше 180 дней вперёд).

| Событие | Название | Место, описание |
|---|---|---|
| Пара | «Философия · семинар» | аудитория, корпус (или «онлайн»); преподаватель; перенос — «Изменено: было …, причина …»; ссылка на пару |
| Отменённая пара | «Отменено · Философия» | `STATUS:CANCELLED`, `TRANSP:TRANSPARENT`; причина |
| Тренировка (подтверждённая) | «Физкультура · <секция>» | место, тренер |
| Экзамен, зачёт | «Экзамен · <дисциплина>» | аудитория; 2 ч (в данных только начало — помечено как примерное) |
| Срок работы | «Срок: <работа> · <дисциплина>» | 30 мин до срока; в файле — напоминание за сутки |
| Моя бронь аудитории | «Бронь: ауд. 1206» | корпус, цель брони |

**Не попадает:** баллы, оценки и «сдано/не сдано», заявки и их статусы, уведомления, ФИО других людей кроме
преподавателя пары, номер зачётки. В подписке — только расписание: если ссылка утечёт, видно, где и когда учится
студент, но не его успеваемость и документы.

`UID` стабильный (`lesson-<id>@university`, `sport-…`, `exam-…`, `room-…`) — календарь обновляет событие на месте.
Время в UTC (`…Z`), без VTIMEZONE. Строки по RFC 5545: CRLF, экранирование `\\ ; , \n`, перенос строк по 75 октетам
без разрыва символов UTF-8. Генератор — свой (`src/lib/calendar/ics.ts`, ~100 строк), без зависимостей.

## Безопасность

- **Файл и одно событие** — только по сессии (`studentForApi`), владелец из сессии: пара и экзамен — через группу
  студента, тренировка и бронь — `studentId`. Чужой id → 404. `Cache-Control: private, no-store`, `nosniff`.
- **Подписка — второй открытый эндпоинт с данными студента** (первый — `/verify/[token]`): календарь телефона ходит без
  cookies, поэтому доступ — по секретному токену в адресе.
  - Токен — HMAC от секрета сервера (HKDF `univ-calendar-v1`) и `(feedId, version)`, 256 бит, base64url. В БД
    (`calendar_feed`: `studentId` unique, `version`, `tokenHash` unique, `rotatedAt`) — только SHA-256 токена; сам
    токен сервер пересчитывает для показа владельцу. Новая ссылка = `version + 1`, атомарно; не чаще раза в минуту.
  - `GET /api/calendar/<token>`: проверка формата, поиск по хешу, иначе 404 без подсказок. Лимит запросов на адрес
    (как у `/verify`), `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`.
  - Токен не пишется в журналы: фильтр Caddy для `/api/calendar/…` (как для `/verify/…`), в коде токен не логируется.
    Не попадает в снимок помощника, уведомления, отчёт и скриншоты (на экране — кнопки, адрес скрыт под «Показать»).
  - Демо-аккаунты общие для жюри: эксперт видит ссылку Алины — это ожидаемо (как пароль). «Выпустить новую ссылку»
    отключает чужую подписку.
- **Контакты** — справочник, не личные данные; отдаём вошедшему студенту (`studentForApi`), id службы — из списка.
- **Печать** — обычная страница кабинета (`requireStudent`), те же функции DAL, дисклеймер на листе.

## Тесты

- Модульные: экранирование и перенос строк ICS (кириллица на границе 75 октетов), CRLF, отменённая пара, vCard.
- Интеграционные (A/B): файл и подписка Алины — только её группа и её брони/тренировки; Тимур не получает событие Алины
  по id (404); новая ссылка — старый токен 404; в подписке нет баллов и заявок; неверный токен 404.
- Ручная проверка: файл и `webcal` на iPhone (команда), Google Календарь по ссылке.

## Не делаем

Apple Wallet для пропуска (нужен сертификат Apple Developer), выгрузку всех данных, двустороннюю синхронизацию.

## После ревью Codex 84 (все замечания приняты)

- **В подписке нет свободного текста:** причина переноса и цель брони — только в файле и одном событии (по сессии).
  В подписке перенос — «Изменено» и прежнее время, без причины.
- **Брони и тренировки — свои выборки по диапазону и владельцу**, не `listMyRoomBookings()` (там только будущие).
  Отменённая бронь и тренировка из ленты пропадают — подписанный календарь убирает их при обновлении; отменённая пара
  остаётся с `STATUS:CANCELLED`. Результаты аттестаций в календарь не выбираются вовсе (не `getMyStudyEvents`).
- **Генератор:** `VERSION`, `PRODID`, `CALSCALE`, `METHOD:PUBLISH`, `DTSTAMP` у каждого события,
  `Content-Type: text/calendar; charset=utf-8`. `SEQUENCE` не выводим из `LessonChange` (откат удаляет историю):
  подписку клиент перечитывает целиком, UID стабилен при переносе, отмене и возврате.
- **Смена секрета сервера** отключает все подписки (как сессии): при открытии «Календарь и печать» сервер видит, что
  пересчитанный токен не совпадает с хешем, и выпускает новый. Первый выпуск — `upsert` по `studentId`; новая ссылка —
  `update … where version = прежняя and rotatedAt < минуту назад` (две ротации подряд — одна проходит).
- **Утечки:** путь ленты — `/api/calendar/feed/<token>`, фильтр журнала Caddy закрывает его вместе с `/verify/…`;
  заголовки защиты и на 404/429. Google: предупреждение «Google получит адрес и события; новая ссылка отключит доступ,
  но скачанное не удалит»; инструкция «с компьютера → Другие календари → По URL» (мобильный Google Календарь
  подписку не добавляет). Канонический адрес — HTTPS, `webcal://` — кнопка для iPhone. Частоту обновления и
  напоминания определяет календарь — не обещаем.
- **Тесты:** A/B для каждого вида события (пара, экзамен/срок, тренировка, бронь); ротация — только своя; CRLF и
  `;,\` в тексте (ICS и VCF); диапазон файла ограничен сервером; в ленте нет баллов, результатов, причин и целей брони.
