# План: раскрытие вместо перегруза

Идея капитана (11.11): списки короткие, а подробности открываются нажатием. Можно пройти по цепочке
«пара → преподаватель → его расписание», «пара → корпус», «дисциплина → контрольные».
Прогнозы по баллам убираем.

## Новые страницы (только для вошедшего студента, внутри `(cabinet)`)

| Маршрут | Что показывает | Куда ведёт дальше | Доступ |
|---|---|---|---|
| `/lessons/[id]` | Дисциплина, тип, дата и время, статус и **вся** история изменений (`LessonChange`), аудитория, онлайн | дисциплина, преподаватель, корпус (+ маршрут в Яндекс Картах), следующая пара по этой дисциплине | `id` + `offering.groupId = моя группа`, иначе 404 |
| `/courses/[id]` (`CourseOffering`) | Баллы X / 100 и текущая оценка по шкале, все контрольные (дата, баллы, «на проверке»), форма контроля и дата | пары дисциплины (ближайшие 3), преподаватели | `id` + `groupId = моя группа`; результаты только `studentId = я` |
| `/teachers/[id]` | Публичный профиль: ФИО, должность, «ведёт у вас» (дисциплины моей группы), расписание преподавателя на неделю (`?week=YYYY-MM-DD`) | свои пары → `/lessons/[id]`; пары других групп — без ссылки | профиль и расписание видны любому вошедшему студенту; несуществующий → 404 |
| `/buildings/[id]` | Название, адрес, метро, маршрут; мои пары и тренировки в этом корпусе на неделе | пары → `/lessons/[id]` | данные корпуса общие; список пар — только мои |

### Что считается публичным
Расписание преподавателя публично, как на сайтах вузов: время, дисциплина, тип, **код группы**,
аудитория, статус. Не публичны: оценки, списки студентов, заявки, уведомления, записи на физкультуру.
DAL преподавателя выбирает только эти поля (`select`), без `include` связей со студентами.

## Упрощение существующих экранов

- **Карточка пары** (`LessonCard`) целиком становится ссылкой на `/lessons/[id]`.
  Внутри остаются время, название, место, преподаватель и короткая отметка «Изменено» / «Отменено».
  Кнопка маршрута и подробности переносов уходят на страницу пары. Заодно уходит проблема с переносом строки
  «Маршрут… м. …» на узком экране. Вложенных ссылок нет.
- **Учёба**: строка дисциплины = название, `X / 100`, бейдж (текущая оценка или «зачтено»),
  одна строка «Дальше: <контрольная>, до <дата>». Вся строка ведёт на `/courses/[id]`.
  Убираем темп, прогноз, «зону риска», «до B ещё N», полосу со штриховкой и длинную сноску про прогноз.
  Прошлые семестры — свёрнутым `<details>`.
- **Сегодня**:
  - главная карточка «Следующая пара» ведёт на `/lessons/[id]`, кнопка маршрута остаётся;
  - «Требует внимания»: дедлайн ведёт на `/courses/[id]`, а не на `/grades`;
  - список «Пары сегодня» — компактные карточки;
  - блок «Новое» убираем: колокольчик уже есть в шапке.
- `src/lib/grading.ts`: удаляем `pace`, `forecast`, `atRisk`, `passReachable` и их тесты;
  остаются сумма, оценка по шкале и баллы на проверке.
- Мелочи со скриншотов: `devIndicators: false`, «г..» после даты.

## Навигация назад
Ссылка «← назад» с `router.back()` и запасным `href` на родительский раздел, если страница открыта по прямой ссылке.

## DAL (`src/server/dal/`)
- `lessons.ts` → `getMyLesson(id)`.
- `courses.ts` → `getMyCourse(id)`.
- `teachers.ts` → `getTeacher(id, weekStart)`: ведёт ли пару преподаватель, определяется так:
  `teacherId = id` или (`teacherId = null` и `offering.leadTeacherId = id`).
  Флаг `mine` — по `offering.groupId`.
- `buildings.ts` → `getBuilding(id, weekStart)`.

Каждая функция вызывает `requireStudent()`. Чужое → `notFound()`.

## Тесты доступа (интеграционные, пара A/B из разных групп)
- A открывает пару группы B → 404; дисциплину группы B → 404.
- В `/courses/[id]` своей группы — только результаты A.
- `getTeacher` возвращает только разрешённые поля: проверка формы объекта, нет `results`, `studentId`, `bookings`.
  Пары других групп помечены `mine: false`.
- `getBuilding`: в списке пар только пары группы A и тренировки A.
- Несуществующие id → 404.

## Решения после ревью Codex → [codex/10-drilldown-plan.md](../ai-log/codex/10-drilldown-plan.md)

1. Публичное расписание преподавателя: без истории переносов и их причин.
   Исключение из правила «расписание только своей группы» записано в `AGENTS.md`.
   Корпус без моих пар — пустой список, не 404.
2. Тесты: третий студент C в группе A (без входа в систему, только данные) с другими оценками и записями.
   Проверяем:
   - что A не видит результатов C;
   - что A может открыть преподавателя чужой группы;
   - пустой корпус;
   - состав вложенных объектов публичного ответа.
3. Ничего персонального в общем кеше: результаты DAL не кешируем по ID.
4. Ссылка из расписания выбирается по `source`: пара → `/lessons/[id]`, тренировка → `/sport`.
5. Баллы ≠ результат аттестации. «Зачтено» и оценку показываем только из результата итоговой точки.
   Посреди семестра при сумме ≥ 60 пишем «порог пройден», при сумме < 60 — «до 60 ещё N», а не «F».
6. Прогноз и темп удаляем. `passReachable` оставляем: «даже с максимумом за оставшееся до 60 не дотянуть» —
   это арифметика. Тесты суммы и достижимости остаются.
7. Главная карточка «Следующая пара»: ссылка на пару — заголовок, маршрут — отдельная кнопка, без вложенных `<a>`.
8. Next.js 16:
   - `await params`;
   - проверка доступа через DAL в начале страницы, до любых `Suspense`;
   - `notFound()` не глушим `catch`;
   - настоящий HTTP 404 проверяем curl.
9. «Назад» — постоянная ссылка на родительский раздел, без `router.back()`.
10. В DTO расписания и дедлайнов добавляем `offeringId` и id преподавателя через `select`.
11. В карточке пары короткое «перенесено на 17:00» или «другой корпус»; история на странице пары свёрнута.
    Расписание преподавателя — только текущая неделя.
12. Не делаем сейчас: произвольные недели, биографию и контакты преподавателя, тренера как `Teacher`.
