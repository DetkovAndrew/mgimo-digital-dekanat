# План: аватарки студентов

Запрос капитана: «добавь возможность аватарок».

Статус: реализовано 12.11.2026. После ревью плана (Codex 23) добавлено: проверка всей структуры файла, а не только
сигнатуры (обрезанные файлы, APNG и анимированный WebP, данные после конца PNG — отказ), не чаще 10 замен в час,
`serverActions.bodySizeLimit` 256 КБ, подпись «Фото видно только вам». Смену аккаунта в соседней вкладке ловит
проверка сессии в `src/components/assistant.tsx` (перезагрузка страницы).

## Решение
- Хранение в PostgreSQL: таблица `StudentAvatar` (`studentId` PK → `StudentProfile`, onDelete Cascade; `data bytea`,
  `mime`, `updatedAt`). Файлы на диск не пишем: данные переживают перезапуск и переезд вместе с БД.
- Обработка в браузере: фото обрезается по центру в квадрат и сжимается холстом до 256×256 (WebP, если браузер не
  умеет — JPEG). Серверную библиотеку не добавляем (sharp тянет libvips под LGPL; правило — только разрешающие лицензии).
- Сервер (Server Action `uploadMyAvatar`, владелец только из сессии): принимает один `File` ≤ 200 КиБ, тип
  `image/webp | image/jpeg | image/png`, сигнатура файла (magic bytes) обязана совпасть с типом; размеры из заголовка
  картинки ≤ 512×512. Иначе — ошибка, БД не меняется. `removeMyAvatar` удаляет свою строку.
- Отдача: `GET /api/avatar` — только своя аватарка из сессии (никакого id в URL), 404 если нет. Заголовки:
  `Content-Type` из БД (из белого списка), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`,
  `Cache-Control: private, no-store`. Чужие аватарки сейчас нигде не показываются.
- Интерфейс: профиль — круг с фото или инициалами, «Изменить фото» / «Удалить фото», состояния загрузки и ошибки;
  шапка телефона и пункт «Профиль» на десктопе показывают фото. В URL добавляется `?v=<updatedAt>` для обновления.

## Тесты (A/B)
- A загружает → GET от A отдаёт байты A; GET от B → 404; удаление B не трогает A.
- Подмена: PNG-сигнатура с типом `image/webp`, HTML с типом картинки, файл больше лимита, размеры больше 512 → отказ.
