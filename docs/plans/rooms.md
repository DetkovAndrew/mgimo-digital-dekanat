# План: интерактивная карта корпуса и бронирование аудиторий

Статус: реализовано 12.11.2026 (ревью плана — Codex 18). Отличия от плана: ГК — кольцо коридоров вокруг двора (крыло 2 сверху, 1 и 3 по бокам, снизу вход и лекционные),
схема вытянута по высоте, чтобы на 360 px номера читались; каждая аудитория выходит в коридор или холл (`plans.test.ts`); поиск свободных аудиторий для помощника — функция `find_free_rooms`, ответ собирает сервер. Запрос капитана: план корпуса «очень примерно, но красиво», тык на аудиторию →
её расписание и брони → забронировать; отдельно — «Заявки → Забронировать аудиторию → корпус → аудитория».
Плюс помощник: «как называется справка» → ссылка с заполненной формой; помощь с бронью → ссылка на аудиторию и день.

## Корпуса и нумерация (обезличенно, схематично)

- Схемы — не реальные планы, а условные, но нарисованы в стиле поэтажного плана: серая подложка, белые коридоры, аудитории —
  ячейки стена к стене с проёмом двери в коридор или холл (место двери считает `placeDoors`), значки-квадраты у лестниц и туалетов.
- **ГК** (`kronv`, «Кронверкский, 49»): 3 крыла вокруг двора, угловые холлы с лестницами, 4 этажа. Номер **XYAB**: X — крыло (1–3), Y — этаж, AB — номер.
  Пример: 2337 — крыло 2, этаж 3, ауд. 37.
- **Корпус М** (`lom-m`): атриум, коридор вверх к угловому холлу и два крыла вокруг двух дворов, 3 этажа (X = 1).
- Остальные корпуса — без схемы (страница корпуса как сейчас).
- В каждом схематичном корпусе по 1–2 **коворкинга** (бронируются студентами) и 2–3 бронируемые переговорные/аудитории.
- Схема задаётся одним описанием в коде `src/lib/campus/plans.ts` (крылья, этажи, аудитории: номер, тип, вместимость,
  бронируемость). Из него же seed создаёт строки `Room`; раскладку на SVG считает функция по тому же описанию.
  Все аудитории из расписания этих корпусов присутствуют в описании (проверяется тестом).

## Данные (миграция `prisma migrate diff` + `migrate deploy`, без reset)

- `Room`: `id` (`kronv-2337`), `buildingId`, `number` («2337»), `wing`, `floor`, `kind` (LECTURE_HALL, CLASSROOM, COMPUTER_LAB,
  LAB, COWORKING, MEETING), `capacity`, `bookable`, `title?` («Коворкинг „Атриум“»). Уникально `(buildingId, number)`.
- `Lesson.roomId?` → `Room` (seed сопоставляет «ауд. 2337» + корпус). Строка `Lesson.room` остаётся для показа.
- `RoomBooking`: `id`, `roomId`, `studentId`, `startsAt`, `endsAt`, `purpose` (≤ 120), `status` (CONFIRMED, CANCELLED),
  `createdAt`, `cancelledAt?`. CHECK: `endsAt > startsAt`. Индексы `(roomId, startsAt)`, `(studentId, startsAt)`.
- Seed: брони вымышленных студентов (занятость коворкингов), 1 бронь Алины.

## Правила брони (демонстрационные, показываются в интерфейсе)

- Только `bookable` аудитории; с 08:00 до 21:00 МСК; шаг 30 мин; длительность 30–180 мин; окно — 7 дней вперёд.
- Не пересекается с занятиями в этой аудитории (кроме отменённых) и с подтверждёнными бронями.
- Не больше 2 будущих броней у студента и 1 на день.
- Гонки: транзакция с `SELECT … FOR UPDATE` строки `Room`, затем проверки и вставка (как у физкультуры с `sport_week`).
- Отмена своей брони до её конца; чужую — 404.

## Доступ (AGENTS.md)

- Расширяем исключение «публичные справочники для вошедших студентов»: аудитория (номер, корпус, тип, вместимость) и её
  расписание на 7 дней — время, дисциплина, тип, код группы, статус, **без id чужих пар и истории переносов**
  (как публичное расписание преподавателя). Чужие брони — только интервал «занято», без студента и цели.
- Свои брони — полностью; создание/отмена — `studentId` только из сессии, zod, Server Actions.
- Тесты A/B: список/чтение/отмена чужой брони → 404; подстановка чужого владельца; в данных аудитории нет `studentId`,
  `purpose` чужих броней и id чужих пар; гонка двух броней на один слот → одна успешна; квоты; пересечение с парой.

## Интерфейс

- `/rooms` — «Аудитории»: выбор корпуса (карточки; у схематичных — «План»). Вход: «Заявки» → «Забронировать аудиторию»,
  страница корпуса (раскрытие), ссылки на аудиторию в карточке пары.
- `/rooms/[building]` — план: вкладки этажей, SVG-схема (крылья разного цвета, аудитории по типу: цвет + подпись номера;
  занятые сейчас — штриховка; мои брони — обводка), под схемой — легенда и переключатель «Списком» (доступность и 360 px).
  `?room=2337&d=2026-11-13` — выбранная аудитория открывается в панели снизу (на десктопе — справа):
  расписание дня (пары и брони), дни недели чипами, бронирование: чипы свободного начала + чипы длительности + цель → «Забронировать».
  Нативный `<select>` не используем (правило набора).
- SVG: каждая аудитория — `<a>` с `aria-label` «Аудитория 2337, компьютерный класс, 24 места, сейчас свободна»;
  клавиатура — Tab по аудиториям; масштаб — `viewBox`, ширина 100%, на телефоне этажи меньше по высоте.
- «Мои брони» — на `/rooms` и в «Сегодня» (если бронь сегодня).

## Помощник

- Снимок: мои брони; список бронируемых аудиторий схематичных корпусов (номер, тип, вместимость, корпус); правила брони.
- Ссылки, которые сервер разрешает **по шаблону** (не только из списка): `/rooms/<корпус из списка>?room=<номер из списка>&d=<дата в окне>`.
- Заявки с заполненной формой: `/requests/new?type=<тип>&<поле>=<значение>` — только поля типа `text`/`select` из каталога,
  значение select — из его вариантов, text — до 100 символов; форма лишь подставляет значения, студент видит и правит их,
  сервер проверяет как обычно. Пример: «справка для военкомата» → `?type=study_certificate&destination=военкомат`.
- Помощник по-прежнему ничего не бронирует и не подаёт: только ссылка, действие — нажатием студента.
