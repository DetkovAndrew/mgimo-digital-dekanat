# Электронный пропуск (демо)

Задача 39: быстрый QR на `/pass`. Входы в навигации и на «Сегодня» подключает Claude; эти файлы здесь не меняются.
На карточке всегда видно: «Демо-пропуск для конкурса. Не открывает турникеты».

- Серверный DAL получает владельца из `requireStudent`, профиль — из `getMyProfile`, своё фото — из `getMyAvatarUrl`.
- `GET /api/pass` использует `studentForApi`; анониму JSON 401, сотруднику 403. У всех ответов `private, no-store`.
- QR: только `UNIV-PASS:v1:<токен>`, без имени, ID, группы или номера зачётки. Токен — первые 18 байт HMAC-SHA256
  от JSON `[studentId, floor(now / 30000)]`, base64url. Ключ HMAC: HKDF-SHA256 от `BETTER_AUTH_SECRET`, пустая соль,
  info `univ-pass-v1`, длина 32 байта. Отсутствующий секрет даёт 503; запасного ключа и журналирования нет.
- Ответ — `{payload, expiresAt}`, `expiresAt` — ISO UTC. `X-Pass-Time` помогает считать срок по часам сервера.
  Необязательный заголовок `X-Pass-Owner` сверяется с сессией и защищает от смены аккаунта под открытым профилем.
- Клиент проверяет сессию, отменяет запросы при уходе, скрывает истёкший QR. Предварительный запрос — за 2 секунды;
  поскольку API отдаёт текущее окно, повторный запрос делается на его границе. После возврата во вкладку — обновление.
  При сетевой ошибке — понятное сообщение и кнопка. Без хранения пропуска в localStorage или общем кеше.
- Используется уже установленная `uqr@0.1.3` (MIT), без новых зависимостей: SVG в `img`, версия 3/M, тихая зона
  4 модуля, 222×222 px. Чёрный/белый — цвета самого QR-изображения, постоянные в обеих темах. Разметка — в токенах.
- Компактная карточка для 360×740; часть общего нижнего отступа компенсирована внутри страницы, навигация защищена.
- Проверки: модульные — границы окна, разделение студентов/секретов, формат и QR; интеграционные — A/B/A,
  401/403, смена владельца и безопасная ошибка без секрета, no-store.
