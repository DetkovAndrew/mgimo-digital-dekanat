# Раздел «Сервисы»

Запрос капитана (14.11): «сделать страницу с сервисами — Wi-Fi, печать и так далее, прям круто надо реализовать».
Цель: не витрина ссылок, а работающие мини-сервисы, которые студент открывает каждую неделю. Все порядки — демо.

## Навигация

- Нижнее меню на телефоне: Сегодня · Расписание · Учёба · Заявки · **Сервисы**. Спорт переезжает в «Сервисы»
  (крупная плитка с баллами) и остаётся на «Сегодня»: во вкладках — ядро ТЗ (расписание, успеваемость, заявки).
- Боковое меню на десктопе: добавляется «Сервисы», остальное без изменений.

## `/services` — хаб

- «Быстро»: 4 крупные плитки с живыми данными — Пропуск (QR), Wi-Fi (сеть и логин), Печать (осталось N страниц,
  заданий в очереди), Найти свободную аудиторию.
- Разделы: «Кампус» (физкультура с баллами, аудитории и брони, схемы корпусов), «Помощь» (IT-поддержка и гостевой
  пропуск — заявки из каталога, вопрос в деканат), «Контакты» (деканат, IT-поддержка, часы работы — демо).

## `/services/wifi`

- **Сеть University** (WPA2-Enterprise): логин — логин кабинета, личный пароль Wi-Fi. Пароль не хранится:
  `HMAC(HKDF(BETTER_AUTH_SECRET, "univ-wifi-v1"), [studentId, version])` → 12 символов без похожих букв, по 4 через
  дефис. По умолчанию скрыт; «Показать», «Скопировать». «Сменить пароль» увеличивает `version` (таблица
  `wifi_credential`: studentId PK, version, rotatedAt), не чаще раза в 10 минут. Только свой: id в адресе нет.
- **Гостевая сеть University Guest** (WPA2-PSK): код дня `HMAC(key, ["guest", день МСК])`, действует до 23:59 МСК,
  QR `WIFI:T:WPA;S:University Guest;P:<код>;;` (uqr, как у пропуска) — гость подключается камерой. Код общий для всех.
- «Как подключиться»: Android, iPhone, Windows, macOS — шаги с настройками EAP (PEAP / MSCHAPv2, домен
  `radius.university.example`, системные сертификаты). Проверку сертификата отключать не советуем.
- «Не подключается?» → заявка `it_support` с `topic=wifi` (предзаполнение из ссылки уже есть).

## `/services/print` — печать по коду

Как в вузовских системах «печать с любого принтера»: задание → код → вводишь код у принтера.
- **Баланс**: 100 страниц в месяц (демо), цветная страница = 4. Израсходовано = сумма `cost` заданий месяца (МСК)
  в статусах «в очереди» (не истекшие) и «напечатано». Отмена и истечение возвращают страницы — без фоновых задач.
- **Новое задание**: выбор PDF. **Файл не покидает устройство** (в демо печатается задание, а не документ): браузер
  считает страницы по `/Type /Pages … /Count N` (максимум), иначе — по `/Type /Page`; файл больше 20 МБ не читается;
  число страниц всегда можно поправить, не вышло — студент вводит сам. На экранах — пометка «демо»: сети и принтеры
  вымышлены. Копии 1–5, двусторонняя, ч/б или цвет; стоимость считается сразу. Сервер принимает только имя файла
  (до 120 символов, без управляющих), страницы 1–200, копии, флаги; стоимость считает сам.
- **Ждут печати**: имя, параметры, стоимость, крупный код из 6 цифр, срок (24 ч). «Отменить». Демо-выпуск:
  «Напечатать на принтере…» — выбор исправного принтера, статус «напечатано», время, принтер.
- **Принтеры**: 4 штуки у коворкингов и деканата (`src/lib/campus/printers.ts`, комнаты со схем), статусы
  «работает» / «мало тонера» / «нет бумаги» (на нём печать недоступна); ссылка на схему с комнатой и маршрутом.
- **История**: последние 10 заданий.

Таблица `print_job`: id, studentId → student_profile (cascade), fileName, pages, copies, color, duplex, cost, code,
status QUEUED | PRINTED | CANCELLED, printerId?, createdAt, expiresAt, printedAt?. CHECK: pages 1–200, copies 1–5,
cost > 0, code `^\d{6}$`. Частичный уникальный индекс кода среди QUEUED. Индекс (studentId, createdAt).

## Доступ и гонки

- DAL `src/server/dal/print.ts`, `src/server/dal/wifi.ts`: `requireStudent()`, запросы `where: { id, studentId }`,
  чужое → 404 и без изменений. Студент не задаёт стоимость, статус, код, владельца.
- **Одна блокировка студента** (`SELECT … FROM student_profile WHERE id = $1 FOR UPDATE`) на создание, выпуск и
  отмену задания; время «сейчас» берётся после получения блокировки. Иначе выпуск у границы срока и создание нового
  задания могли бы одновременно посчитать резерв (ревью Codex 47). Создание: остаток и не больше 3 в очереди.
  Выпуск: `updateMany` с условием QUEUED и не истекло; на неисправном принтере — отказ.
- Код задания уникален среди QUEUED (частичный индекс); при совпадении — повтор всей транзакции, до 5 раз. Задание
  ищется по id и владельцу, код — только для показа.
- Бюджет — месяц **создания** задания (МСК): напечатанное 1 декабря задание от 30 ноября списано с ноября.
- Смена пароля Wi-Fi — один атомарный `INSERT … ON CONFLICT DO UPDATE … WHERE rotatedAt < now() - 10 мин RETURNING`:
  из двух одновременных смен проходит одна.
- Server Actions + zod, штатная защита Origin. Страницы динамические (`private, no-store`).

## Тесты

Модульные: подсчёт страниц PDF (обычный, без /Count, мусор), стоимость, формат пароля Wi-Fi, код гостя меняется
по дням. Интеграционные A/B: список только своих, отмена/выпуск чужого — 404 без изменений, подстановка studentId
игнорируется, квота и лимит очереди, параллельные создания не превышают квоту, истёкшее не печатается, неисправный
принтер; смена пароля Wi-Fi меняет только свой, не чаще раза в 10 минут.

## Помощник

Ссылки `/services`, `/services/wifi`, `/services/print` — в шаблоны `src/lib/assistant/links.ts`; в снимок —
остаток страниц печати (без имён файлов). Пароль Wi-Fi и коды печати в снимок не попадают.
