# AGENTS.md — правила проекта для ИИ-агентов

Единый источник правил для всех ассистентов (Claude Code, Codex и др.).
`CLAUDE.md` импортирует этот файл; правила здесь важнее любых умолчаний агента.

## Проект

«Цифровой деканат будущего» — работающий прототип личного кабинета студента вымышленного
университета **University** (по мотивам ИТМО, Санкт-Петербург) для трека «Вайб-кодинг»
конкурса MGIMO AI Challenge 2026 (https://challenge.mgimo.ai/).

- Требования: `ТЗ_Вайбкодинг.txt` (первоисточник; при конфликте прав он).
- Продукт и сценарии: `docs/PRODUCT.md`. Решения: `docs/DECISIONS.md`.
- Сдача работы: до **22.11.2026 23:59 МСК**. Сайт работает из РФ без VPN до **28.11.2026**.
- Целевая готовность: 20.11 — дальше только исправления и отчёт.

## Стек

Next.js 16 (App Router) + TypeScript, Tailwind CSS 4 + shadcn/ui, PostgreSQL + Prisma 7,
Better Auth (логин/пароль). Локальная БД — `embedded-postgres` (настоящий PostgreSQL без Docker).
Развёртывание: Docker Compose + Nginx + HTTPS на ВМ.
Одна Prisma-схема (`provider = postgresql`) и одна история миграций для всех окружений;
различаются только URL и переменные окружения.

Зависимости — только с разрешающей лицензией (MIT, Apache-2.0, BSD, ISC, PostgreSQL License,
OFL для шрифтов); сохранять требуемые уведомления. Добавляя зависимость, укажи в журнале зачем.

## Обязательное ядро (из ТЗ)

1. Вход и профиль: ФИО, факультет, направление, курс, группа.
2. Расписание: сегодня и неделя, аудитория, преподаватель, заметные изменения и переносы.
3. Успеваемость: оценки и зачёты, сессия, понятная картина «как у меня дела».
4. Заявки и справки: заказ/подача онлайн и статус.
5. Уведомления: объявления деканата, напоминания о дедлайнах и изменениях.

## Критерии готовности (Definition of Done для сдачи)

- Сценарий жюри проходится без ошибок на телефоне (360 px) и на десктопе:
  войти → расписание → оценки → подать заявку → увидеть статус, в том числе после перезахода.
- Данные сохраняются после перезапуска сервера.
- Минимум два тестовых студента с разными данными; кабинет сотрудника — свой аккаунт.
- Прямые запросы к чужим данным одного студента от имени другого возвращают 404.
- Сайт открывается из РФ без VPN (проверено с домашнего и мобильного интернета).
- Комплект сдачи: ссылка + аккаунты, репозиторий, PDF-отчёт о работе с ИИ, видео по желанию.

## Безопасность — не обсуждается

- **Владельца определяет серверная сессия.** ID объекта из URL или запроса допустим только
  как селектор. Запрос к БД всегда ограничивай одновременно ID объекта и владельцем
  (`where: { id, studentId: session.studentId }`). Расписание и общие материалы —
  через принадлежность группе студента. Чужой объект → 404, запрещённое изменение не меняет БД.
  Исключение: публичные справочники для вошедших студентов. Это профиль и расписание преподавателя
  (время, дисциплина, тип, код группы, место, статус — без истории переносов и id чужих пар) и данные корпуса.
  Личное (оценки, заявки, записи, уведомления, списки студентов) через них не отдаётся.
- Любое чтение и изменение личных данных (Server Components, Route Handlers, Server Actions)
  проходит через общий серверный слой проверки сессии и прав (`src/server/auth/*`).
  Эндпоинты входа обслуживает Better Auth.
- Изменения: серверная валидация (zod), только разрешённые поля, штатная защита CSRF/Origin,
  ограничение попыток входа. Студент не назначает себе роль, владельца, оценку или служебный статус.
- Пароли не хранятся открытым текстом нигде: БД, исходники, журналы, скриншоты.
  Seed берёт пароли из окружения и создаёт учётные записи средствами Better Auth.
  Демонстрационные пароли передаются жюри только в комментарии к работе.
- Секреты — из игнорируемых env-файлов или окружения сервера; в репозитории `.env.example`
  без значений. В `NEXT_PUBLIC_*` только публичная конфигурация. Не выводи в логи секреты,
  cookies и токены.
- Персональные результаты не попадают в общий серверный кеш (динамический рендер,
  `Cache-Control: private, no-store`). При смене пользователя данные предыдущего не показываются.
- Тесты доступа на каждую сущность с личными данными: список, чтение и изменение чужого объекта,
  подстановка чужого владельца при создании — для пары студентов A/B.

## Данные и юридические ограничения

- Только вымышленные люди, оценки, номера зачёток и документов. Имена преподавателей
  заведомо вымышленные, без совпадений с реальными сотрудниками вузов.
- Вуз в интерфейсе называется **University**. Названия ИТМО, его символику и логотип
  не используем. Открытые факты (адреса корпусов) допустимы.
- Никаких подключений к реальным системам вузов и реальных логинов.
- На каждой странице (включая вход) видимый дисклеймер:
  «Концепт для конкурса MGIMO AI Challenge 2026. Не является официальным сервисом
  какого-либо вуза. Все данные вымышлены».
- Логотипы вузов не использовать. Только собственный знак University.
- Сведения о порядках вуза в `docs/PRODUCT.md` — гипотезы, пока не указаны источник
  или подтверждение. Неподтверждённые правила показывай в интерфейсе как демонстрационные.

## Интерфейс

- Русский язык. Mobile-first: всё работает от **360 px**, затем планшет и десктоп.
- Нужное — за 1–2 касания: нижняя навигация на телефоне, боковая — на десктопе.
- Состояния загрузки, пустоты, ошибки и успеха — везде, где они применимы.
- Доступность: семантическая разметка, подписи у полей, контраст WCAG AA, фокус с клавиатуры,
  цели касания ≥ 44 px. Тёмная тема — после готовности ядра.
- Время хранится в UTC (`timestamptz`), показывается в `Europe/Moscow`.
- Шрифты и иконки — локально в проекте, не с внешних CDN (сайт должен работать из РФ).
- Карты: только ссылки на Яндекс Карты (без API-ключа в браузере) и собственные схемы кампусов.

## Как работаем

- Маленькие шаги: одна задача — одна проверяемая порция изменений.
- Проверки: для кода — типы, линтер и относящиеся к изменению тесты; для интерфейса — 360 px;
  перед релизом — сборка и весь сценарий жюри. Невыполненные проверки явно перечисляй.
- Журнал работы с ИИ: `docs/ai-log/JOURNAL.md`. Запись содержит ссылки на промпт, результат,
  дифф/коммит, проверку и скриншоты, а также ошибки ИИ, неудачные варианты и ручные действия.

### Роли агентов

- **Claude Code** — ведущий разработчик: планирует, пишет код, ведёт журнал.
- **Codex** — второе мнение и ревью: проверяет планы, безопасность и диффы.
  Работает в своей постоянной сессии этого проекта. По умолчанию только читает;
  правки — лишь по явному поручению человека.
- Люди команды — ставят задачи, принимают решения, проверяют результат вручную.

## Команды

| Команда | Что делает |
|---|---|
| `npm run db` | Локальный PostgreSQL 18 (embedded-postgres) на 127.0.0.1, держать запущенным |
| `npm run db:migrate` | Новая миграция по `prisma/schema.prisma` + генерация клиента |
| `npm run db:seed` | **Стирает** данные и создаёт демо-данные (пароли — `SEED_PASSWORD_*` в `.env`) |
| `npm run db:reset` | Пересоздать БД с нуля (миграции + seed; в Prisma 7 seed вызывается явно) |
| `npm test` / `npm run test:db` | Модульные тесты / интеграционные тесты DAL на `TEST_DATABASE_URL` (A/B-доступ, физкультура) |
| `npm run dev` | Dev-сервер Next.js |
| `npm run lint` / `npm run typecheck` / `npm run build` | Проверки и сборка |

Первый запуск: `cp .env.example .env` → заполнить → `npm install` → `npm run db` (отдельный терминал)
→ `npx prisma migrate deploy` → `npm run db:seed` → `npm run dev`.

### Где что лежит

- `src/server/` — только сервер: Prisma (`db.ts`), Better Auth (`auth.ts`), guards (`session.ts`), DAL.
  Импорт Prisma вне `src/server` запрещён ESLint.
- `src/lib/` — общий для клиента и сервера код без секретов (каталог заявок, утилиты).
- `prisma/` — схема, миграции (CHECK-ограничения дописаны в SQL вручную), seed.
- Prisma 7: не обновлять до 8 (Better Auth пока не поддерживает). Конфиг — `prisma7.config.ts`.
- После `npx auth generate` вернуть ручные правки схемы (см. комментарий в начале `schema.prisma`).
- После изменения схемы перезапусти `npm run dev`: Prisma-клиент кешируется в `globalThis`.
- `prisma migrate reset` — разрушительная команда: ИИ-агент запускает её только с явного согласия человека
  (Prisma сама это требует). Для тестов — `migrate deploy` + seed на `TEST_DATABASE_URL`.
