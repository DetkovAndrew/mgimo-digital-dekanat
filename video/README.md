# Промо-ролик кабинета

37 секунд, 1920×1080, 60 к/с, H.264 High 4.2 (MP4). Сценарий капитана: телефон парит на размытом фоне и листает кабинет;
камера поворачивается и приближается, подписи перечисляют функции; заявка вылетает из телефона и прилетает
на ноутбук уже одобренной («На любом устройстве»); свет гаснет, включается тёмная тема; финальная карточка
с адресом и дисклеймером.

Всё на экранах — настоящие снимки локального кабинета (Алина, демо-данные), ответ помощницы — настоящий ответ
GigaChat. Модели телефона и ноутбука собраны из примитивов three.js, без чужих моделей, логотипов и узнаваемых
деталей конкретных производителей.

## Полная версия: демонстрация

`dekanat-hiphop-full.mp4`, 3:29 — для конкурса («видео-демонстрация до 5 минут: как студент пользуется
кабинетом, в том числе с телефона»). Тизер целиком, заставка «Как студент пользуется кабинетом», затем 11 шагов
сценария на телефоне: вход, «Сегодня», расписание, успеваемость, заявка на справку, деканат на ноутбуке берёт её
в работу и отмечает готовой, уведомление и PDF с QR-кодом, страница проверки, перенос пары (деканат на ноутбуке
переносит онлайн-семинар Алины в переговорную — у студентки уведомление, «Изменено» в расписании, новая аудитория
и путь до неё), помощница с бронью, маршрут по схеме корпуса, профиль и тёмная тема. Финальная карточка с адресом
и дисклеймером. Версия 15.11 (10 шагов, 2:54) — до кабинета сотрудника с переносом пар. Пересняты 19.11 на текущем
интерфейсе (звезда в знаке, мягкие вкладки «Заявок»): справку студентка находит поиском по каталогу «Заявки», помощницу
просит «Забронируй переговорную в понедельник с 15 до 16» — на завтра у Алины уже есть демо-бронь, а правило — одна в день.
20.11 маршрут по схеме переснят по часам ролика: проход Инвиктии и наезд камеры раньше шли по часам съёмки и
пролетали в разы быстрее, чем на сайте (план 9 → 13.8 с). Стекло телефона и ноутбука бликует на ~40% меньше.

Всё на экранах — настоящий проход по локальному кабинету: логин и пароль набираются по буквам (пароль — точками),
заявка подаётся и обрабатывается по-настоящему, ответ помощницы — настоящий ответ GigaChat, бронь — настоящая.
QR-код и адрес проверки на кадре PDF размыты: токен справки — секрет.

```bash
# 1. Съёмка (пишет в локальную БД: заявка, её обработка, перенос пары, бронь переговорной)
PW_A=… PW_STAFF=… node demo-capture.mjs                    # все акты → captures/demo/
PW_A=… PW_STAFF=… node demo-capture.mjs reschedule,moved   # перенос пары; затем в корне: npm run db:undo-staff
PW_A=… node demo-capture.mjs assistant,route               # пересъёмка отдельных актов
ROUTE_HREF="/rooms/lom-m?room=1221&d=2026-11-20&from=entrance#plan" PW_A=… node demo-capture.mjs route   # только схема, если на «Сегодня» нет «Как пройти»
DEMO_FPS=6 PW_A=… node demo-capture.mjs browse             # черновик в 10 раз быстрее — подобрать прокрутку
# 2. Кадры-проверки и ролик
node render.mjs stills 40,95,150 --program full
node render.mjs video --program full --music music.json --only dekanat-hiphop --bitrate 16e6   # out/dekanat-hiphop-full.mp4
```

Как устроено: `demo-capture.mjs` снимает «планы» — кадры 60 к/с, на каждом выполняются шаги, чьё время пришло:
касание (координаты пишутся в meta, сцена рисует круг), набор текста по буквам, действие, которого съёмка ждёт.
Переход по ссылке — после плана: смену экранов (сдвиг, растворение) рисует сцена. Ответ помощницы придерживается,
пока на кадрах идёт «думает…», таймер её «^ ^» перед открытием окна идёт по времени ролика. Деканат — снимки
страницы целиком до и после каждого щелчка (`desk()` в съёмке; планов ноутбука может быть несколько); прокрутку
и курсор рисует сцена. `scene/demo.js` — монтаж: шаги,
подписи, переходы, камера; длительности планов берутся из `captures/demo/meta.json`. При одном варианте звука
MP4 упаковывается по ходу кодирования и пишется на диск частями (место под метаданные в начале резервируется заранее):
три минуты в памяти вкладки целиком не помещаются. Музыка в полной версии —
тот же хип-хоп: после 63 с трека по очереди повторяются целые такты (`loops` в `music.json`), в демонстрации
на 3 дБ тише.

## Как собрать

```bash
cd video && npm install
# 1. Снимки (кабинет запущен: npm run dev в корне). Пароли — только из окружения.
PW_A=… node capture.mjs phone            # кадры телефона → captures/phone/
PW_A=… PW_STAFF=… node capture.mjs flow  # ПИШЕТ В БД: Алина подаёт справку, деканат отмечает «Готово»
# повтор без новой заявки: REQUEST_ID=<id> … node capture.mjs flow
# 2. Проверочные кадры и ролик
node render.mjs stills 1,9,23.6,26.5,31.7,35   # → out/stills/
node render.mjs video                           # → out/dekanat.mp4, ~8 мин на CPU
node render.mjs frames dekanat.mp4 1,26.5       # кадры из готового MP4 → out/frames/
python3 check-mp4.py out/dekanat.mp4            # дорожки: кодек, размер, кадры, длительность
# 3. Музыка: треки в music/ (не в git), разбор и ролики со звуком
node render.mjs analyze                         # темп, доли, громкость → out/analysis.json
node render.mjs video --music music.json        # out/<вариант>.mp4 и .wav на каждый трек
```

## Звук

Варианты — в `music.json`: трек и привязка к таймлайну (`offset` — время трека в начале ролика, `root` — тоника
для «дзынь»). Привязка подобрана по разбору (`analyze`): у корпоративного трека такт ровно 2 с — смена функций
попадает в такт, его концовка совпадает с «свет гаснет»; у остальных — вступление, брейк или финал трека на
ключевых моментах. Поверх музыки — синтезированные акценты (`scene/audio.js`): щелчок касания, «вжух» вылета,
«тук» посадки, «дзынь» одобрения, спад света, низкий удар финала; ночью музыку закрывает фильтр.

Звук в MP4 — Opus: AAC эта сборка Chromium не кодирует. Opus в MP4 играют браузеры, VLC, плеер Windows 11,
YouTube/Rutube/VK; для старых плееров рядом лежит WAV сведения — его можно подложить в любом редакторе (AAC).

Треки — с Pixabay (капитан, 15.11): AudioCopper «Company Corporate», alexguz «Funk & Breakbeat», JonasBlakewood
«Background Music», pumpupthemind «Hip Hop Beat». Лицензия Pixabay: использование в ролике без указания авторства,
но не распространение самих файлов — поэтому `music/` в `.gitignore`.

## Как устроено

- `lib.mjs` — общее для съёмки: вход, ожидание отрисовки, прокрутка с дробными пикселями, CSS-анимации по времени
  ролика (бесконечные — от общего начала, разовые — с момента появления, переходы страниц доигрываются сразу).
- `capture.mjs` — Playwright: телефон 390×800 при DPR 2, 60 к/с, прокрутка задаётся по кадрам (плавно и одинаково
  при каждом запуске). Браузер прокручивает на целые пиксели — дробная часть добирается сдвигом `<main>`, иначе на
  разгоне и торможении страница стоит и прыгает; смещения по кадрам — в `captures/phone/<экран>/scroll.json`; ноутбук 1280×800 при DPR 2 до и после одобрения, светлая и тёмная тема.
- `scene/` — three.js: `models.js` (телефон, ноутбук, карточка, тени), `screens.js` (экраны: строка состояния,
  сдвиг страниц, касание, подсветка строки, круговое включение тёмной темы), `overlay.js` (фон, подписи, знак
  University, финальная карточка), `main.js` (таймлайн, камера по ключам, рендер и кодирование).
- Кодирование — WebCodecs `VideoEncoder` (avc1 High 4.2: 1080p при 60 к/с) в самом Chromium, упаковка — `mp4-muxer` (MIT).
  ffmpeg не нужен; GPU тоже: рендер идёт в SwiftShader, ~200 мс на кадр.
- Зависимости: three (MIT), mp4-muxer (MIT), playwright (Apache-2.0); шрифт Onest (OFL) — из `assets/fonts/onest`.
